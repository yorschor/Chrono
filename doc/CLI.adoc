= Chrono CLI

== Introduction

The Chrono CLI is a command‑line tool for managing your project’s version information stored in a version.yml file, and for performing related Git operations (branching, tagging, releasing). It provides a set of commands to interact with the version.yml file and your project repository.

* Initialize a project for Chrono
* Read and write version numbers
* Bump specific version components
* Create branches and tags based on your branch‑naming schema
* Automate release workflows

== Overview

[source, text]
----
└── Chrono/
    ├── init      Start init wizard for current directory 
    ├── get       Reads and prints the current version.
    ├── set       Sets the version to a specific value. 
    ├── bump      Increments a version component (major, minor, patch, build).
    ├── tag       Creates a git tag using the current branch’s tag pattern.
    ├── release   Creates a release branch based on the target branch schema.
    ├── branch    Creates a feature/hotfix branch based on the current branch schema.
    └── info      Prints Chrono CLI version and credits.
----


== Commands

All commands except the "Init" and "Info" command require a valid version.yml file to exist in the current of a parent directory as well as a initialized git repo be present.

== Common Options 

All commands support the following options:

=== -d|--debug  

Enables debug logging.

=== -t|--trace

Enables trace logging. Also prints exceptions if any occur.

=== -i|--ignore-dirty

Ignores dirty repositories. If a repository is dirty the short hash will be replaced by the dirty-repo placeholder.

== Get

Gets the current version of the project.

* -n, --numeric -> 
Print only the numeric portion (e.g. 1.2.3.4), omitting any prerelease tag.

* -e, --useEnvVars -> 
Fall back to VERSION_MAJOR, VERSION_MINOR, etc., if present in the environment. Should be used in most CI scenarios.

* -p, --gitRoot <path> -> 
Manually specify the Git repository root (defaults to discovering from CWD).

== The Set command

Sets the current version of the project. It does so by simply replacing the version key in the version.yml.yml file.

* <Version> -> 
A semantic version string to set the project to. eg. 1.2.3.4

NOTE: The following commands include the option -c|--commit which will commit the changes to the version.yml file. Use with care :) 

== the "Bump" command

Increments one component of the version. Updates only the requested part and resets lower-order fields as per semantic‑versioning conventions.

* <component> ->
One of: major, minor, patch, or build.
(Note: build only available if version.yml defines a build field.)

== The "Tag" command

The tag command creates a new tag in the git repo according to the *_current_* branch config present. 

== The "Branch" command

The branch command creates a new branch in the git repo according to *_current_* branch config present. 

== The "Release" command

The release command creates a new branch in the git repo according to *_target_* branch config specified.
