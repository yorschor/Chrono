== CI Example

=== Gitlab
Example for Gitlab CI Component that writes both numeric and          full version to a .env file.

[source,yaml]
----
get:version: 
  stage: prepare
  image: docker.io/yorschor/chrono:1.0.0
  script: 
    - chrono get -ie 
    - echo "PROJECT_VERSION=$(chrono get -nie)" >> build.env
    - echo "PROJECT_FULL_VERSION=$(chrono get -ie)" >> build.env

  artifacts:
    reports:
      dotenv: build.env
----

=== Generic CI (OneDev and others)

For CI systems without a built-in provider, opt in explicitly with `CHRONO_CI` and pass branch, tag and commit through the `CHRONO_*` variables.
With `CHRONO_CI` set, `-e` needs no git repository. Without one, `version.yml` is searched from the current directory upwards
(or pass the file path as `[Target]`). Inside a git repository the usual repository search applies. A leading `refs/heads/` or `refs/tags/` is stripped.
The other `CHRONO_*` variables are ignored unless `CHRONO_CI` is set. If `CHRONO_CI` is set but `CHRONO_COMMIT_SHA` or both
`CHRONO_BRANCH` and `CHRONO_TAG` are missing, Chrono fails with an error naming the missing variable.

[%autowidth,frame=none,options="header"]
|===
| Variable | Meaning
| CHRONO_CI | Any non-empty value, e.g. `true`. Switches Chrono to the generic provider
| CHRONO_BRANCH | Branch name (required unless `CHRONO_TAG` is set)
| CHRONO_TAG | Tag name (leave empty for branch builds)
| CHRONO_COMMIT_SHA | Full commit hash (required)
|===

OneDev command step:

[source,yaml]
----
- !CommandStep
  name: chrono version
  image: mcr.microsoft.com/dotnet/sdk:9.0
  interpreter: !DefaultInterpreter
    commands: |
      dotnet tool install -g Chrono.CLI
      export PATH="$PATH:$HOME/.dotnet/tools"
      chrono get -e > .chrono-version
  envVars:
  - name: CHRONO_CI
    value: 'true'
  - name: CHRONO_BRANCH
    value: '@branch@'
  - name: CHRONO_TAG
    value: '@tag@'
  - name: CHRONO_COMMIT_SHA
    value: '@commit_hash@'
----
